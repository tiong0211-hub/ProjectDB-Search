# ProjectDB-Search 사용 설명서

도면·스캔 PDF·사진·기술 메모 등 오래된 프로젝트 문서를, 자연어로 질의해서
**"어느 문서를 봐야 하는지"**를 빠르게 찾아주는 도구입니다. 문서 내용을
요약하거나 대신 읽어주지는 않습니다 — 정확한 문서 위치와 근거만 안내합니다.

**검색은 파일 형식과 무관하게 모든 파일에 적용됩니다** — PDF·스캔·사진은
물론 Word/Excel/PowerPoint 같은 Office 문서도 파일명 기준으로 찾아지고,
**"Open file"**로 그대로 열립니다. 다만 내용을 직접 읽는 **정밀 스캔(2단계,
OCR)**만은 예외입니다 — Office 파일은 보안상 열람이 제한된 경우가 많아
이 프로그램이 어떤 파일이 실제로 보안 파일인지 구분할 수 없으므로, 정밀
스캔은 Word/Excel/PowerPoint의 내용을 절대 읽지 않고 항상 우회합니다
(PDF와 스캔 이미지의 내용만 읽습니다).

설치나 프로그래밍 지식이 필요 없습니다. 압축 풀고 더블클릭하면 끝입니다.

> 이 파일(`사용설명서.md`)은 `run.bat`과 같은 폴더에 들어있습니다 — 나중에
> 다시 찾고 싶으면 프로그램을 압축 해제한 폴더를 열어보세요.

---

## 1. 처음 실행하기

1. 전달받은 `ProjectDB-Search` 폴더 전체를 원하는 위치에 압축 해제합니다.
   (폴더를 통째로 옮겨도 되고, 폴더 안 파일을 낱개로 옮기면 안 됩니다.)
2. 폴더 안의 **`run.bat`**을 더블클릭합니다.
3. 몇 초 후 웹 브라우저가 자동으로 열리며 검색 화면이 나타납니다.
   - 브라우저가 안 열리면 주소창에 `http://127.0.0.1:8765` 를 직접 입력하세요.
4. 창을 닫으면 프로그램도 함께 종료됩니다. 다시 쓰려면 `run.bat`을 다시
   실행하세요.

> 첫 실행 시 "게시자를 확인할 수 없습니다" 같은 Windows 경고가 뜰 수
> 있습니다. "추가 정보" → "실행"을 눌러 진행하세요. 계속 문제가 되면
> IT 담당자에게 화이트리스트 등록을 요청하세요.

---

## 2. 문서 인덱싱하기 (최초 1회, 또는 문서가 바뀌었을 때)

검색하려면 먼저 어떤 폴더의 문서를 찾아볼지 한 번 알려줘야 합니다. 인덱싱은
**두 단계**로 나뉘어 있습니다 — 1단계(파일명 인식)는 항상 몇 초~몇십 초
안에 끝나고, 그 즉시 검색을 쓸 수 있습니다. 2단계(정밀 스캔)는 파일명만으로
식별되지 않은 문서에 한해 실제 내용을 읽는 단계로, 느릴 수 있지만 원할 때만
실행하면 됩니다.

1. 상단 메뉴에서 **"Index documents"**를 클릭합니다.
2. **"Document folder"** 칸에 문서들이 들어있는 폴더 경로를 입력합니다.
   예: `\\사내서버\공유폴더\프로젝트문서` 또는 `C:\Shared\ProjectDocs`
3. **"Build index"** 버튼을 클릭합니다.
   - 진행률 표시줄과 함께 현재 상태가 보입니다: "폴더 검색 중" → "파일명 읽는
     중 3,200 / 20,000" → "검색 인덱스 생성 중". 화면이 멈춘 게 아니라
     어디까지 진행됐는지 바로 확인할 수 있습니다.
   - 이 페이지를 벗어나거나 창을 닫아도 백그라운드에서 계속 진행되며, 다시
     돌아오면 진행 상황이 이어서 표시됩니다.
   - 실수로 잘못된 폴더로 시작했거나 그냥 멈추고 싶다면 진행률 표시줄 아래
     **"Cancel"**을 누르세요. 그때까지 처리된 파일은 그대로 검색 가능한
     상태로 남고, 나중에 다시 "Build index"를 누르면 멈춘 지점부터 이어서
     진행됩니다 — 처음부터 다시 하지 않습니다.
4. "Done." 메시지와 함께 몇 개의 파일을 인덱싱했는지 나타나면 **1단계
   완료**입니다 — 보통 몇 초 안에 끝납니다. **이 시점부터 바로 검색을 쓸 수
   있습니다.**
5. 화면에 "N file(s) couldn't be fully identified..." 메시지가 보이면, 그
   문서들은 아직 파일명만으로 검색됩니다. 내용까지 검색에 반영하려면
   **"Start deep scan"** 버튼을 누르세요.
   - 진행률 표시줄이 나타나며, 이 페이지를 벗어나도(다른 탭 이동, 창 최소화)
     백그라운드에서 계속 진행됩니다. 나중에 이 페이지로 다시 돌아오면 진행
     상황이 그대로 이어서 표시됩니다.
   - 도중에 멈추고 싶으면 **"Cancel"**을 누르세요. 이미 처리된 문서는
     그대로 저장되고, 나중에 다시 "Start deep scan"을 누르면 **멈춘 지점부터
     이어서** 진행됩니다 — 처음부터 다시 하지 않습니다.
6. **"Go search →"**를 눌러 검색 화면으로 이동합니다.

**나중에 문서가 추가되거나 바뀌었다면?** 같은 화면에서 같은 폴더 경로로
다시 "Build index"를 누르면 됩니다 — 바뀐 파일만 다시 처리하므로 빠릅니다.
전체를 처음부터 다시 읽게 하려면 **"Force full re-index"**에 체크하세요.

### 처음 한 번은 이렇게 설정해두면 정밀 스캔이 훨씬 줄어듭니다

파일명/폴더명만으로 프로젝트명과 문서 종류가 둘 다 파악되는 문서는 애초에
정밀 스캔(2단계) 대상에서 빠집니다. 그런데 사내 실제 프로젝트명이 기본
설정에는 들어있지 않기 때문에, 처음 인덱싱해보면 정밀 스캔 대상이 예상보다
많이 나올 수 있습니다. 이때는 IT/담당자에게 다음을 요청하세요:

- 명령 프롬프트에서 `run_console.bat`을 실행한 뒤
  `projectdb-search suggest-projects --corpus-root <문서 폴더 경로>`를 실행하면,
  실제 폴더 구조에서 뽑아낸 프로젝트명 후보 목록과 설정 파일에 붙여넣을 수
  있는 블록을 바로 출력해줍니다.
- 그 내용을 `config/default_config.toml`의 `[project_name_patterns]`에
  붙여넣고 저장한 뒤 `run.bat`을 다시 실행하면, 그 다음 인덱싱부터 정밀
  스캔 대상이 크게 줄어듭니다.

## 3. 문서 검색하기

1. 검색창에 찾고 싶은 문서를 자연어로 입력합니다. 예:
   - `isometric drawing for HX-203`
   - `압축기 데이터시트 2020`
   - `compressor station memo safety review 2015`
2. 검색창 옆 드롭다운에서 몇 건까지 볼지, 그리고 어떤 순서로 볼지 고를 수
   있습니다.
   - **표시 개수**: 기본값 25건, 최대 200건. 후보 문서가 화면에 보이는
     것보다 많을 때는 결과 목록 위에 "N document(s) matched — showing
     M"처럼 안내가 뜨고, 목록 아래 **"Show N more"** 버튼으로 (다시
     검색하지 않고도) 더 펼쳐볼 수 있습니다 — "Data sheet"처럼 너무
     포괄적인 검색어라 같은 종류의 문서가 수백 건 묶여 나올 때 유용합니다.
   - **정렬 기준**: "Relevance"(기본, 관련도순) 외에 "Newest first"(이
     도구가 그 파일을 최근에 등록/갱신한 순서)와 "File type"(같은 확장자
     끼리 화면에서 모아서 보여줌)도 고를 수 있습니다.
   - **"Narrow search"**를 펼치면 검색 범위를 더 좁힐 수 있습니다:
     - **File type**: 특정 확장자(예: `.pdf`만, `.docx`만)로 결과를
       제한합니다.
     - **Folder**: 몇 글자만 입력하면 일치하는 상위 폴더가 자동완성으로
       나타납니다 — 선택하면 알약 모양 태그로 추가되고, 여러 개를 계속
       추가할 수 있습니다(그 폴더들 중 어디에라도 속한 문서를 찾습니다).
       태그의 `✕`를 누르면 제거됩니다. 태그를 하나도 안 넣으면 지금처럼
       전체 폴더에서 검색합니다. 프로젝트/부서 폴더가 여러 개 섞인 대형
       코퍼스에서 동명이인 파일 문제를 줄이는 데 유용합니다.
   그래도 원하는 문서가 안 보이면 장비 태그나 프로젝트명 같은 좀 더
   구체적인 단어를 검색어에 추가해보세요.
3. **Search** 버튼을 누르거나 Enter를 칩니다.
4. 후보 문서가 점수순(또는 위에서 고른 정렬 기준)으로 나타나며, 각 결과
   아래에 **왜 이 문서가 선택됐는지**(어떤 항목이 일치했는지) 설명이
   함께 표시됩니다.
5. **"Open file"**을 클릭하면 실제 문서가 열립니다. 일부 파일(특히
   Word/Excel/HWP 등 사내 문서보안 대상으로 분류되는 형식)은 이 버튼
   대신 "Open via folder"라는 안내만 보입니다 — 사내 문서보안 솔루션이
   브라우저를 거쳐 열리는 사본은 인식하지 못해 거부하는 경우가 많기
   때문입니다. 이때는 **"Show in folder"**를 눌러 Windows 탐색기를 열고
   그 안에서 원본 파일을 직접 더블클릭하면 정상적으로 열립니다.
   **"Show in folder"**는 그 문서가 들어있는 폴더를 탐색기에서 바로 열고
   해당 파일을 선택된 상태로 보여줍니다 — 같은 폴더의 다른 관련 문서도
   함께 확인하고 싶을 때도 유용합니다.

**약간 오타가 있거나, 파일명 일부만 기억나도 괜찮습니다** — 예를 들어
"compresor"처럼 한 글자가 틀리거나, "compressor"만 입력해도 "CompressorStation"
같은 붙여 쓴 파일명을 찾아냅니다(다만 점수는 정확히 일치했을 때보다 낮게
표시됩니다).

**결과에 "ambiguous" 표시가 있다면**, 후보들의 점수가 낮거나 비슷하다는
뜻입니다. 관리자가 사내 Claude Enterprise 연동을 설정해뒀다면 이 경우
자동으로 한 번 더 판단을 거치며 "LLM re-ranked" 표시가 함께 나타납니다.

## 4. 결과가 맞는지 알려주기 (피드백)

검색 결과가 정확했는지 알려주시면 추후 검색 정확도를 개선하는 데
사용됩니다 (자동으로 설정이 바뀌지는 않고, 담당자가 주기적으로 검토합니다).

- 원하는 문서를 찾았다면 그 결과 옆 **"Correct"** 버튼을 클릭하세요.
- 셋 다 아니라면 아무 결과의 **"Not this one"**을 클릭해도 됩니다.
- 클릭하면 "Thanks — feedback logged." 메시지가 뜹니다. 그걸로 끝, 별도
  입력은 필요 없습니다.

---

## 5. 검토 대기 문서 확인하기 ("Review queue")

스캔 품질이 나쁘거나 손상된 파일은 자동 인식에 실패할 수 있습니다. 이런
문서는 검색이 막히지 않고 파일명만으로 계속 검색되지만, 별도로
표시됩니다.

상단 메뉴의 **"Review queue"**에서 이런 문서 목록을 확인할 수 있습니다.
필요하면 해당 문서의 파일명을 사람이 직접 정리해주는 것도 도움이 됩니다
(예: `scan_0091.pdf` → `RiversidePlant_Isometric_HX-330.pdf`로 변경 후
재인덱싱).

## 6. 문제가 생겼을 때

- **브라우저가 안 열려요** → `run_console.bat`을 대신 실행해보세요. 검은
  창에 에러 메시지가 그대로 표시됩니다. 그 내용을 IT 담당자에게
  전달해주세요.
- **인덱싱이 실패하거나 멈춰요** → 폴더 경로에 오타가 없는지, 네트워크
  드라이브라면 연결이 살아있는지 확인하세요.
- **검색이 이상하게 느려요** → 검색 자체는 1단계 인덱싱만 끝나면 문서
  수천 건에서도 항상 밀리초 단위로 빠릅니다. 느리다고 느껴진다면 검색이
  아니라 **정밀 스캔(2단계)**과 혼동하신 것일 수 있습니다 — 정밀 스캔은
  파일명만으로 식별 안 된 PDF/스캔 문서의 내용을 실제로 읽는 단계라 문서당
  몇 초씩 걸릴 수 있고, 원래 느립니다. §2의 "처음 한 번은 이렇게 설정해두면
  정밀 스캔이 훨씬 줄어듭니다"를 참고해 사내 프로젝트명을 등록해두면 정밀
  스캔 대상 자체가 크게 줄어듭니다.
- **정밀 스캔이 너무 오래 걸려요** → 도중에 "Cancel"로 멈췄다가 나중에
  다시 시작해도 됩니다 — 이미 처리된 문서는 다시 하지 않고 이어서
  진행됩니다. 급하지 않은 문서라면 굳이 정밀 스캔을 돌리지 않아도 파일명
  검색만으로 계속 쓸 수 있습니다.
- **Word/Excel/PowerPoint 파일이 검색에 안 나와요** → 파일명/폴더명만으로
  프로젝트명과 문서 종류를 둘 다 알아낼 수 없으면, PDF와 마찬가지로 정밀
  스캔 대기 상태로 표시됩니다 — 다만 Office 파일은 정밀 스캔에서도 내용을
  절대 읽지 않으므로("Review queue"에 표시되어 계속 파일명 기준으로만
  검색됩니다), 검색이 잘 안 되면 파일명 자체를 프로젝트명/문서 종류가
  드러나게 바꿔주는 것이 가장 확실합니다(§5 참고).
- **"Show in folder"를 눌렀는데 파일이 아니라 상위 폴더만 열려요** →
  원드라이브처럼 폴더 구조가 아주 깊은 경우, 전체 경로가 Windows
  탐색기가 처리할 수 있는 길이를 넘어서면 정확한 파일 대신 그 파일이
  들어있는 폴더까지만 열어드립니다(버튼에 "Folder only (path too long)"
  라고 표시됩니다) — 탐색기 자체의 한계라 이 프로그램에서 완전히 없앨
  수는 없지만, 열린 폴더 안에서 파일을 직접 찾으시면 됩니다. 검색 결과
  자체와 **"Open file"**로 문서를 여는 기능은 경로 길이와 무관하게 정상
  동작합니다.
